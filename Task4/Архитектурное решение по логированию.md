# Архитектурное решение по логированию

## Системы для сбора логов

**1. Shop API**
- Создание заказа
- Изменение статуса заказа
- Ошибки валидации
- Запросы в БД
- Публикация в RabbitMQ

**2. CRM API**
- Получение заказа на обработку
- Действия менеджера (подтверждение, отклонение)
- Изменение статуса заказа
- Запросы в БД
- Публикация/получение из RabbitMQ

**3. MES API**
- Получение заказа на расчет
- Расчет цены
- Ошибки парсинга 3D-модели
- Действия оператора (взял в работу, произвел, упаковал)
- Изменение статуса заказа
- Запросы в БД
- Публикация/получение из RabbitMQ
- Загрузка/скачивание из S3


### Логи с уровнем INFO

**Создание заказа**: логируем время, идентификатор покупателя, номер заказа, статус заказа

**Изменение статуса заказа**: логируем время, номер заказа, старый статус, новый статус, кто изменил

**Действия менеджера**: логируем время, идентификатор менеджера, номер заказа, действие (подтверждение, отклонение)

**Действия оператора**: логируем время, идентификатор оператора, номер заказа, действие (взял в работу, произвел, упаковал)

**Расчет цены**: логируем время, номер заказа, рассчитанную цену, время расчета

**Публикация в RabbitMQ**: логируем время, номер заказа, название очереди

**Получение из RabbitMQ**: логируем время, номер заказа, название очереди

**Запрос в БД**: логируем время, номер заказа, тип запроса (INSERT, UPDATE, SELECT), длительность запроса

### Другие уровни логирования

**WARN** - используем для нестандартных ситуаций, которые не являются ошибками:
- Медленный запрос в БД: логируем время, длительность запроса, тип запроса
- Повторная попытка подключения к RabbitMQ: логируем время, количество попыток
- Большой размер 3D-модели: логируем время, номер заказа, размер файла
- Долгий расчет цены: логируем время, номер заказа, время расчета

**ERROR** - используем для ошибок, которые нужно исправлять:
- Ошибка валидации заказа: логируем время, номер заказа, текст ошибки, детали валидации
- Ошибка подключения к БД: логируем время, текст ошибки, стек трейс
- Ошибка публикации в RabbitMQ: логируем время, номер заказа, название очереди, текст ошибки
- Ошибка парсинга 3D-модели: логируем время, номер заказа, текст ошибки, стек трейс
- Сообщение попало в DLQ: логируем время, номер заказа, название очереди, текст ошибки, количество попыток

**DEBUG** - используем только в dev/test окружениях:
- Детали HTTP-запросов: логируем заголовки, параметры запроса
- Детали SQL-запросов с параметрами: логируем полный запрос
- Содержимое сообщений в RabbitMQ: логируем тело сообщения

## Мотивация

**Проблема**: нет логов, разбираем со слов клиента
- Не знаем что происходило в системе когда клиент столкнулся с проблемой
- Разработчики тратят много времени на воспроизведение проблемы
- Поддержка не может помочь клиенту - нет данных

**Что даст логирование**:
- Видим что происходило в системе в момент проблемы
- Находим причину за минуты
- Можем помочь клиенту без воспроизведения проблемы
- Видим историю всех действий по заказу

**Для бизнеса**:
- Быстрое решение проблем клиентов
- Снижение нагрузки на поддержку
- Уменьшение времени простоя
- Прозрачность для клиентов

**Метрики, на которые повлияет логирование**:

1. **Время решения инцидентов**
   - Было: несколько часов на воспроизведение и поиск проблемы
   - Станет: несколько минут с логами - видим что произошло

2. **Нагрузка на поддержку**
   - Было: много обращений "где мой заказ?", поддержка не может ответить
   - Станет: поддержка видит в логах что происходит с заказом
   - Уменьшение времени обработки обращения

3. **Процент потерянных заказов**
   - Было: не знаем где и почему теряются
   - Станет: видим в логах где заказ застрял, почему не перешел дальше
   - Можем исправить проблему быстрее

4. **Время поиска проблемы**
   - Было: долго ищем причину, долго чиним
   - Станет: быстро находим причину в логах, быстро чиним

5. **Лояльность клиентов**
   - Было: клиенты недовольны - долго ждут решения проблемы
   - Станет: быстро решаем проблемы, клиенты довольны
   - Ожидаем повышение лояльности

### Что делать в первую очередь

**Этап 1: Shop API**
- Логирование создания заказов
- Логирование публикации в RabbitMQ
- Логирование ошибок валидации
- Логирование медленных запросов в БД
- Это точка входа заказов в систему - критично для отслеживания

**Этап 2: MES API**
- Логирование получения заказа из RabbitMQ
- Логирование расчета цены
- Логирование ошибок парсинга 3D-модели
- Логирование работы с S3
- Здесь часто зависают заказы при расчете цены

**Этап 3: CRM API**
- Логирование получения результата расчета
- Логирование действий менеджера
- Логирование изменений статуса заказа
- Связывает Shop и MES, важно для полной картины

## Предлагаемое решение

### Технологии

**ELK Stack** (Elasticsearch + Logstash + Kibana):
- **Elasticsearch** - хранение и поиск логов
- **Logstash** - сбор и обработка логов
- **Kibana** - визуализация и поиск

### Компоненты решения

**1. Логирование в каждом API**
- Shop API (Java): добавить библиотеку логирования
- CRM API (Java): добавить библиотеку логирования
- MES API (C#): добавить библиотеку логирования
- Логи в JSON формате
- Обязательные поля: timestamp, level, service, trace_id, order_id, message

**2. Logstash**
- Собирает логи от всех API
- Парсит JSON
- Отправляет в Elasticsearch

**3. Elasticsearch**
- Хранит логи
- Индексирует по полям (order_id, trace_id, service, level)

**4. Kibana**
- Web-интерфейс для поиска логов
- Дашборды для метрик

**5. Filebeat**
- API пишут логи в файлы
- Filebeat читает файлы и отправляет в Logstash

### Политика безопасности

**1. Скрытие чувствительных данных**

Не логируем:
- Пароли, токены, API ключи
- Номера кредитных карт
- Персональные данные - только user_id
- Полные SQL-запросы с параметрами (могут содержать секреты). Заменяем параметры на `***`.

**2. Доступ к логам**

- Роль "Support": может смотреть логи типов INFO, WARN и ERROR
- Роль "Developer": может смотреть все логи
- Роль "Admin": полный доступ к Kibana

Интеграция с корпоративным сервисом аутентификации.

**3. Сетевая изоляция**

- Logstash, Elasticsearch, Kibana - только во внутренней сети
- Нет доступа из интернета
- Filebeat может отправлять в Logstash

**4. Шифрование**

- Логи передаются по HTTPS
- Логи в Elasticsearch шифруются

**5. Audit log**

- Логируем кто и когда смотрел логи в Kibana
- Алерт при подозрительной активности

### Политика хранения

**Индексы**:
- Отдельный индекс под каждый сервис: `shop-api-logs`, `crm-api-logs`, `mes-api-logs`
- Индексы по дням: `shop-api-logs-2024-01-15`
- Упрощает удаление старых логов

**Время хранения**:
- INFO логи: хранятся 30 дней
- WARN логи: хранятся 60 дней
- ERROR логи: хранятся 90 дней
- DEBUG логи: не пишем в production

**Размер**:

Оценка объема логов:

**Текущая нагрузка** (Например, 30 заказов в день):
- 30 заказов × 20 логов × 500 байт = 300 KB в день для заказов
- С учетом логов операторов, менеджеров, системных событий:
  - INFO: ~10 MB/день
  - WARN: ~5 MB/день
  - ERROR: ~3 MB/день
  - **Итого: ~18 MB в день**

**Хранилище при текущей нагрузке**:
- 30 дней INFO: ~300 MB
- 60 дней WARN: ~300 MB
- 90 дней ERROR: ~270 MB
- **Итого: ~870 MB**

**Прирост каждый месяц**:

Каждый месяц +100 заказов → +3.3 заказа в день → дополнительно ~6 MB в день логов.

Прирост хранилища:
- INFO (30 дней × 6 MB): +180 MB
- WARN (60 дней × 3 MB): +180 MB
- ERROR (90 дней × 2 MB): +180 MB
- **Итого +60 MB каждый месяц**

**Ротация**:
- Автоматическое удаление старых индексов
- При достижении 500 GB - удаляем самые старые логи

## Мероприятия для анализа логов

### Алертинг

**1. Алерт на ERROR логи**: Если за 5 минут > 10 ERROR логов в одном сервисе

**2. Алерт на рост количества логов**: Если количество логов за минуту выросло в 10 раз (возможно DDoS)

**3. Алерт на медленные запросы в БД**: Если за 5 минут > 5 WARN логов "slow query"

**4. Алерт на сообщения в DLQ**: Если сообщение попало в DLQ

**5. Алерт на недоступность сервиса**: Если 5 минут нет логов от сервиса

### Поиск аномалий

**1. Всплеск создания заказов**: Было 4 заказа/сек, стало 10 000 заказов/сек

**2. Всплеск ошибок**: Было 1-2 ERROR/минуту, стало 100 ERROR/минуту

**3. Аномальное время обработки**: Расчет цены вырос

**4. Заказы создаются, но не обрабатываются**: Много "order_created", но нет "status_changed"
